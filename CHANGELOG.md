## 0.1.4 - 2026-10-22

Commit `8b189cbf959f`; release record `pub:sha2-256:d4zgmoan4lz3prmx72iunqliftxzumd5eayyefcjhaw3qwvnqada`.

### Added
- The action can deploy index.html to Cloudflare Pages as well as, or instead of, your own server: set cloudflare-api-token, cloudflare-account-id and cloudflare-project

### Security
- The page names the Subresource Integrity hash of every script and stylesheet it loads (the libraries from INTEGRITY in lib/page.js, the app's own from this release's app/), so a browser refuses a file jsDelivr or anything between serves changed
- The deployed page names the hash of the published index.json, which lists the hash of every recipe file, and the page fetches them with integrity, so changed recipe data is refused; a newer publish is taken only from a newer page on the page's own host (recipe-host page --index)

## 0.1.3 - 2026-10-22

Commit `affd60308a3e`; release record `pub:sha2-256:tt4e3siaqq3ts22imvt4r2fg3m3empiez4ztyyftzxm5jrhm2tza`.

### Added
- A home page of the reader's favourite recipes, starred on the recipe list or a recipe's page and kept in the browser for each recipe repository.
- The recipe list moves from #/ to #/recipes and works like the ingredient list, with filter chips for each category and for breakfast, lunch and dinner tags; #/ is now the favourites page.
- A logo and browser-tab icon: the Sustenaut disc with a steaming pot in place of the sprout.
- Sign-in for readers: a login section in recipe-host.yml (an OpenID Connect issuer and client, and whether reading needs it) signs readers in with the code flow and PKCE, coming back to the same view and ?repo=. Sites without it are unchanged.
- Favourites in the signed-in reader's own bucket: favourites in recipe-host.yml names a service that hands out short-lived links to one file per repository, so they follow the reader between browsers. What the browser kept moves there at the first sign-in.
- recipe-host serve --mock-login previews a site with a local stand-in for the Sustenaut sign-in and favourites service, with test accounts and an in-memory bucket.

### Fixed
- Header links not selected are muted brown instead of Pure CSS grey, and a visited selected link is no longer black on the dark header.
- The logo's pot has no lid line, so the mark reads as a pot and steam without clutter.

### Internal
- npm test writes an LCOV coverage report, which CI gives SonarQube Cloud for its coverage gate.
- The browser tests record which lines of app/app.js they run, and CI runs them in the test job so SonarQube Cloud counts that coverage; test/ is analysed as test code.
